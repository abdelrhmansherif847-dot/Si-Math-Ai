Five families, two rules.

Not five looks handed out to five kinds of picture. Each family has a fixed grammar that never varies, and one axis of variation — and the variant is computed from the question, not chosen per figure.

Two inputs decide every variant below. One has to be authored because no figure can reveal it; the other is already sitting in the spec. Every figure on this page was produced by those rules through the shared renderer — none is hand-set.

Rule one

Authored

reading: shape or value

Does the student have to get a number off the figure, or only judge its shape?

Nothing in the geometry can answer that — it is a property of the question, not of the picture. So it has to be authored, and the stimulus schema has to carry a field for it.

It turns the grid on a function graph on and off, and the reference lines on a chart.

Rule two

Derived

resolutionOf(): how fine the marks are

The coarsest step on which every marked value lands exactly — 1, ½, ¼, ⅕ or ⅒.

Nobody chooses it. It is already in the spec: an endpoint at −2.5 makes it ½, and the figure grows half-step marks so that endpoint sits on one.

It sets tick density on a number line and grid density in coordinate geometry.

Function graphs

✓ Open, with a grid only when the question needs one

Read shape, and sometimes read a value.

The grammar — never varies

  • The curve is the heaviest mark in the figure. Scaffolding always steps back behind it.
  • Scales are not equal. Nothing here needs an x unit to match a y unit, and forcing it wastes the plate.
  • The axes are a plane: arrowheads, and italic x and y at their ends.
  • The window is trimmed to where the curve lives, and the curve is clipped to it.

The one thing that varies — Whether a grid is drawn.

reading: shape
“How many turning points does the graph have?”
reading: value
“What is the value of f(3)?”

reading is authored on the question. shape → no grid. value → a grid, because the student has to get a number off the picture.

Coordinate geometry

✓ Squared paper

Count lengths and identify named points.

The grammar — never varies

  • Equal scales, always. Shape carries meaning here, so a circle must be round and a right angle right.
  • The grid is the measuring instrument and is always present. It is not background.
  • Every vertex the stem names is named on the figure, and so is the origin.
  • The figure is bold enough to sit on top of its own grid.

The one thing that varies — How fine the grid is.

vertices on integers
resolution 1 → one square per unit
a vertex on a half
resolution ½ → half-unit lines appear

Derived, not chosen: the grid step is resolutionOf() of the figure’s own vertices. Integer vertices → a unit grid. A vertex at 2.5 → half-unit lines, so that vertex sits on a crossing.

Data and scatterplots

✓ Screen-native

Locate one observation, or judge a trend.

The grammar — never varies

  • These are measured data, so none of the plane’s conventions apply: no arrowheads, no equal scales, no origin.
  • The data carries a validated hue and is the most saturated thing in the figure.
  • Identity comes from a direct label on the series, never a legend.
  • Nothing is interactive. On a dashboard a tooltip shows the value; on an exam it is the answer.

The one thing that varies — Whether reference lines are drawn.

reading: shape
“Which best describes the association?”
reading: value
“What is the greatest gain below 5 tests?”

The same authored reading as the function family, answered differently: value → horizontal rules, because a value on a chart is read by tracking left. shape → none, because a trend needs no rule to be seen.

A whole, divided

✓ The decided vocabulary

Read one share, or compare two.

The grammar — never varies

  • No axis, so none of the plane’s conventions apply: the shape IS the total.
  • Four fills and no more — the two decided hues, then two neutrals. A fifth part would have to invent a colour, so a fifth part is refused.
  • Every slice names itself at its own rim, with its share. Never a legend.
  • The separator is the paper showing through, not a line of its own.

The one thing that varies — How many panels the one stimulus carries.

two panels
one population, cut two ways
one panel
and a share small enough to test its own label

Not a variant of the figure, a property of the QUESTION: one population cut two ways is one stimulus, because a question comparing a share in the first with a share in the second is only answerable if both describe the same whole.

Number lines

✓ Statement, with adaptive tick density

Read one endpoint and decide open or closed.

The grammar — never varies

  • Endpoint-first: the endpoint is the largest mark in the figure, because open-versus-closed is the question.
  • Only the values the question turns on are named. A number line is not a ruler to be read across.
  • Open and closed are drawn as hollow and filled — semantic, never decorative.
  • The line runs the full width of the text. It is a strip, and it is given a strip’s shape.

The one thing that varies — How dense the ticks are.

endpoint on an integer
resolution 1 → clean line, no minor ticks
endpoint on a half
resolution ½ → half-step ticks, and −2.5 named

Derived: resolutionOf() of the marked values. All integers → no minor ticks. An endpoint at −2.5 → half-step ticks, and that value is named even though it is off the major step.

Tables

✓ Boxed — header band

Find one cell fast, and be certain of its row and its column.

The grammar — never varies

  • Every cell is bounded. Under time, nothing about which row and column a number belongs to is left to alignment.
  • The header is reversed out of solid ink, so it labels the object rather than being its first row.
  • Numerals are tabular and right-aligned; row labels are not.
  • The table sits at the text’s left margin. It is part of the question, not an object placed beside it.
Refused · Panel — reads as UI placed beside the question rather than part of itRefused · Typographic — beautiful, and the slowest to track a row across under time

What this changes downstream

One field is now missing from the schema. reading cannot be inferred from a figure — two questions can share a graph and want different treatments — so exam_stimuli needs to carry it, and exam_stimulus_spec_ok needs to accept it. That is a migration change, and it is worth knowing now rather than after content is inserted.

Everything else is derivable. Grid density, tick density and the totals rank all fall out of values the spec already holds, which is why nothing on this page was hand-set: every figure above was produced by the two rules through the shared renderer.

Shared across all five, and not negotiable per family: the typeface and numeral style, tick treatment and numeral placement, the space around a figure inside a question, and the measure of the column. Those are what make a set of five different treatments still read as one exam.

Production is untouched: the renderer is not wired, no migration exists, and no content has been inserted.
